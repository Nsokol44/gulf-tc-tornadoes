# Post-flip report: coast-assignment rule change (author decision, 2026-11-24)

The primary coast-assignment rule in `code/02_build_sample.py` is now the
latitude-restricted rule: for dual-qualifier storms (qualifying under both
the Gulf and Atlantic definitions), the stratum is set by the storm's
earliest qualifying landfall fix at latitude >= 24.0 N. Single-qualifier
storms keep their only coast; box-only storms keep the box fallback; the
same-timestamp tie still goes to the Gulf. The previous
first-landfall-anywhere rule is now the reported sensitivity. The full
pipeline (`code/run_all.py`, steps 01-07) was rerun end to end on
2026-11-24 (exit 0; log `run_logs/run_all_postflip.log`). The pre-flip
results are preserved verbatim in `results_preflip/` for audit. Nothing
outside `analysis/` was modified.

## 1. Flip-set verification: EXACT MATCH

Before any code change, the pre-flip `results/` directory was copied to
`results_preflip/`. The new rule was then prototyped against the pre-flip
sample and, after implementation, verified again on the rebuilt sample.
Both checks reproduce the target set in the pre-flip
`results/coast_assignment_sensitivity.csv` **exactly**:

No discrepancy arose, so no adjustment to the candidate-fix definition
was needed: the definition that reproduces the target is exactly the one

landfall sets, filtered to latitude >= 24.0 N, earliest per coast, Gulf
wins a same-timestamp tie).

The regenerated `results/coast_assignment_sensitivity.csv` now describes
the reverse direction: the flips the OLD first-landfall-anywhere rule
would produce relative to the new primary. It is generated by step 02 on
every run, contains the same 11 storms and counts in the same CSV format

reversed relative to the pre-flip table (under the old rule, the 10
non-Michelle storms would flip Gulf -> Atlantic and Michelle 2001 would
flip Atlantic -> Gulf).

## 6. Fallback storms under the new rule

Dual-qualifier storms with no qualifying landfall at >= 24.0 N fell back
to the previous first-landfall-anywhere assignment and are logged in
`results/sample_build_log.json` (key
`coast_assignment_fallback_storms_1995plus`). For 1995 and later there
are four:

| Storm | Year | Fallback assignment | Basis |
|---|---|---|---|
| LILI | 1996 | Gulf | landfall |
| LESLIE | 2000 | Gulf | box_only (no landfall fixes at all) |
| GRACE | 2021 | Atlantic | landfall |
| JULIA | 2022 | Atlantic | landfall |

**None of the four contributes any tornado to the 1995-2023 sample**
(0 sampled tornadoes each), so no sampled storm's stratum depends on the
fallback. (The full HURDAT2 qualifying table contains additional pre-1995
fallback storms; they are outside the sample period and do not affect any
result.)

## 7. Implementation notes

- `code/02_build_sample.py`: `qualify_storms` now computes both
  assignments; the >= 24 N rule sets `coast` for dual-qualifier storms,
  the old assignment is retained as `coast_first_landfall_anywhere`
  (with its basis and first-landfall timestamp) in
  `qualifying_storms_two_coast.csv`, and step 02 writes
  `coast_assignment_sensitivity.csv` from the final sample on every run.
  The module docstring describes the adopted rule as primary and the old
  rule as the sensitivity.
- `code/README.md`: the step-02 row and judgment call 2 now describe the
  adopted rule as primary and the first-landfall-anywhere rule as the
  sensitivity.
- Caveat: `results/sampled_storms_first_landfall.csv` is a static
  pre-flip artifact (not generated by any pipeline step) and still shows
  the old assignments in its `assigned_coast` column; it was left as
  archived. Its pre-flip copy is also in `results_preflip/`.
- REBUILD_REPORT.md itself was not edited; this report is its post-flip
  companion. Its section 2 judgment call 1 and section 3-4 coast-specific
  numbers are superseded by sections 3-4 above; its pooled numbers stand.
